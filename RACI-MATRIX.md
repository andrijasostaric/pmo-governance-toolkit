# RACI Matrix

| Deliverable / Decision | Sponsor | Programme Manager | Engineering | Operations | Compliance | Finance |
|---|---|---|---|---|---|---|
| Programme charter | A | R | C | C | C | C |
| Integrated delivery plan | I | A/R | C | C | C | C |
| Technical solution decisions | I | C | A/R | C | C | I |
| Process redesign | I | A | C | R | C | C |
| Control / compliance requirements | I | C | C | C | A/R | I |
| Budget change > agreed tolerance | A | R | C | C | C | R |
| Risk acceptance | A | R | C | C | C | C |
| Go-live readiness | A | R | R | R | R | C |
| Executive status reporting | I | A/R | C | C | C | C |

**R = Responsible · A = Accountable · C = Consulted · I = Informed**

## Working rule
Every material deliverable should have one clearly identifiable accountable owner. Where ownership is unclear, the programme manager resolves or escalates it before the ambiguity becomes a delivery risk.
